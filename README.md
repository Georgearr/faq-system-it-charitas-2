# Charitas IT Issue & FAQ System

Production-oriented internal IT Issue & FAQ platform for Charitas built with a **React + TypeScript** frontend and **Google Apps Script** as the production backend, utilizing **Google Sheets** for persistence.

## Architecture

```text
Local Development:
Vite -> React + TypeScript -> AppAdapter -> MockAdapter -> Mock Data

Production Web App:
GAS Web App (doGet) -> HtmlService -> React Bundle -> AppAdapter -> AppsScriptAdapter -> google.script.run -> GAS Services -> Google Sheets
```

### Adapter Pattern (Non-Negotiable)

The application **never** calls Google Apps Script services directly from React components. All backend communication goes through the `AppAdapter` interface:

- **MockAdapter** - Full local development with deterministic mock data
- **AppsScriptAdapter** - Promise wrappers around `google.script.run` for production

Both adapters expose the identical contract defined in `src/api/AppAdapter.ts`.

## Production Deployment (Google Apps Script)

### Prerequisites

1. Google Cloud Project with:
   - Google Sheets API enabled
   - Google Apps Script API enabled
   - OAuth 2.0 Client ID configured (for Google Sign-In)
2. Google Workspace domain (for organizational deployment)

### Step 1: Create the Bound Spreadsheet

1. Create a new Google Spreadsheet
2. Note the Spreadsheet ID from the URL: `https://docs.google.com/spreadsheets/d/{SPREADSHEET_ID}/edit`
3. In the spreadsheet, open **Extensions → Apps Script**

### Step 2: Configure the Apps Script Project

1. In the Apps Script editor, create the following files:
   - `Code.gs` - Copy from `gas/Code.gs`
   - `appsscript.json` - Copy from `gas/appsscript.json`
   - `index.html` - Generated by `npm run build:gas`

2. Set Script Properties (**Project Settings → Script Properties**):
   ```
   SPREADSHEET_ID = {your-spreadsheet-id}
   GOOGLE_CLIENT_ID = {your-oauth-client-id}
   GOOGLE_CLIENT_SECRET = {your-oauth-client-secret}
   TWILIO_ACCOUNT_SID = {twilio-sid}  # Optional: for SMS/phone verification
   TWILIO_AUTH_TOKEN = {twilio-token}  # Optional
   TWILIO_SERVICE_SID = {twilio-verify-sid}  # Optional
   MAILGUN_API_KEY = {mailgun-key}  # Optional: for email delivery
   MAILGUN_DOMAIN = {mailgun-domain}  # Optional
   ```

3. Run the `setupSpreadsheet()` function once from the Apps Script editor to create all sheets and seed initial data.

### Step 3: Build and Deploy Frontend

```bash
# Build React app and copy to gas/ folder
npm run build:gas
```

This creates a production bundle in `gas/` with:
- `gas/index.html` - Entry point for HtmlService
- `gas/assets/` - JS and CSS bundles

**Important:** Copy the contents of `gas/` to your Apps Script project (replace the existing `index.html` and `assets/` folder).

### Step 4: Deploy as Web App

1. In Apps Script: **Deploy → New Deployment**
2. Type: **Web App**
3. Execute as: **User accessing the web app**
4. Who has access: **Anyone** (or your organization)
5. Deploy and copy the Web App URL

### Step 5: Configure OAuth Redirects

In Google Cloud Console → OAuth 2.0 Client:
- Authorized JavaScript origins: Add your Web App URL
- Authorized redirect URIs: Add `{WEB_APP_URL}/callback` (if using OAuth flow)

## Key Features

### Authentication
- **Email/Password** - Registration, login, verification, password reset
- **Phone/OTP** - SMS/WhatsApp verification flow (mock in dev, Twilio in prod)
- **Google Sign-In** - OAuth 2.0 via Google Identity Services
- **Sessions** - 7-day JWT-like tokens stored in Google Sheets
- **2FA Architecture** - UI placeholder, backend structure ready

### Issue Management
- Create issues (authenticated users + guest submission)
- Status workflow: `open → assigned → in_progress → waiting_for_user → resolved → closed`
- Priority levels: `low, medium, high, urgent`
- Assignment to IT staff
- Public replies + **Internal notes** (IT-only, never visible to users/guests)
- Guest tracking via secure token

### FAQ System
- Category-based organization
- Full-text search + keyword filtering
- Publish/Draft/Archive workflow
- Helpful/Unhelpful feedback
- IT staff management interface

### Role-Based Access Control
| Role | Capabilities |
|------|--------------|
| Guest | Browse FAQs, submit issues, track via token |
| User | Own issues, replies, profile, notifications |
| IT Staff | Issue queue, assignment, status/priority, internal notes, FAQ management |
| Admin | User management, roles, status, categories, audit logs, system config |

### Audit Logging
All security-relevant actions logged:
- Authentication: LOGIN, LOGOUT, REGISTER, VERIFY_*, GOOGLE_LOGIN, PASSWORD_RESET
- Issues: CREATE_ISSUE, UPDATE_ISSUE, REPLY_ISSUE, INTERNAL_NOTE, ASSIGN_ISSUE
- Users: CHANGE_ROLE, CHANGE_USER_STATUS
- FAQ: CREATE_FAQ, UPDATE_FAQ, DELETE_FAQ
- System: UPDATE_CATEGORY, SYSTEM_CONFIG_CHANGED

## Production Blockers (Must Resolve Before Production)

### 🔴 1. Google OAuth ID Token Validation
**File:** `gas/Code.gs` → `loginWithGoogle()`
**Issue:** Function trusts `credentialOrIdToken` parameter as raw Google Subject (`sub`) without cryptographic verification.
**Required:** Implement ID token validation via Google's tokeninfo endpoint:
```javascript
// Required production implementation:
var response = UrlFetchApp.fetch('https://oauth2.googleapis.com/tokeninfo?id_token=' + idToken);
var payload = JSON.parse(response.getContentText());
// Validate: aud === GOOGLE_CLIENT_ID, iss === 'accounts.google.com', exp > now
var verifiedSub = payload.sub;
```
See: https://developers.google.com/identity/gsi/web/guides/verify-google-id-token

### 🔴 2. Insecure Password Hashing
**File:** `gas/Code.gs` → `hashPassword()`
**Issue:** Uses SHA-256 (fast hash) - vulnerable to brute-force/rainbow tables.
**Required:** Implement PBKDF2, bcrypt, scrypt, or Argon2. GAS workaround:
```javascript
// PBKDF2-like implementation using HMAC-SHA256
function hashPasswordPBKDF2(password, salt, iterations = 100000) {
  var key = Utilities.computeHmacSha256(password, salt);
  for (var i = 1; i < iterations; i++) {
    key = Utilities.computeHmacSha256(key, salt);
  }
  return key.map(b => ('0' + (b & 0xff).toString(16)).slice(-2)).join('');
}
```

### 🟡 3. External Provider Integration
- **Twilio** (SMS/WhatsApp): Requires `TWILIO_*` script properties + `UrlFetchApp` calls
- **Mailgun** (Email): Requires `MAILGUN_*` script properties
- **Google Email**: Currently uses `MailApp` (daily quota limits apply)

### 🟡 4. Session Storage
Current implementation uses `PropertiesService.getUserProperties()` which is per-user and not shared across deployments. For production scale, consider a dedicated Sessions sheet with proper indexing.

## Development Guidelines

1. **Never** call `google.script.run` directly from React components
2. **Never** use `SpreadsheetApp`, `MailApp`, `UrlFetchApp` in frontend code
3. All business logic goes in **Services** (`src/services/`)
4. All persistence goes through **Adapters** (`src/api/`)
5. React components only handle **presentation**
